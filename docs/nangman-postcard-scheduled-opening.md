# 낭만엽서 — 특별 우표 예약 개봉 (개발 명세)

상태: 구현 착수 / **실서비스 활성화 금지**, 서버·iOS·웹·R2 보관정책 검증 후 배포.

## 확정 사용자 흐름
1. 발신자가 특별 우표를 선택하고 도착 시간을 설정한다. 1·3·6·12시간, 1·3·7일, 날짜 직접 지정(최대 1년).
2. 업로드 시 서버가 **UTC unlockAt**을 검증하고 기록한다. 클라이언트 시계는 신뢰하지 않는다.
3. 발신자가 카카오톡 공유 버튼을 눌러 **즉시 링크**를 전송한다. 카카오톡 예약 발송 API는 사용하지 않는다.
4. 수신자는 개봉 전에는 봉투와 **도착 예정 시각만** 확인한다. 서버는 이미지·손글씨·발신자명·사진을 내려주지 않는다.
5. UTC unlockAt 도달 시 동일 링크에서 열람 및 손글씨 재생·영상 저장 가능. 도착 후 10일에 만료한다.
6. 수신자 도착 알림은 **명시적 신청 후** 제공. 별도 동의·이메일 검증·발송 인프라 구현 전에는 알림 버튼을 활성화하지 않는다.

## 데이터 및 보안
- 일반 우표: createdAt + 10일 만료, 기존 동작 유지.
- 특별 우표: 예약 가능 기간 **업로드 후 1시간~365일**, expiresAt = unlockAt + 10일.
- API POST meta: `unlockAt`(ISO 8601 UTC). 반드시 서버에서 우표 종류가 special인지 검증.
- GET /api/nangman/postcard/:token: 잠금 중 `423 {code:"locked", unlockAt:"ISO"}`; 이 응답에 메타·발신자·획·배경 URL 없음.
- GET /api/nangman/postcard/:token/background: 잠금 중 423; 이미지 바이트 절대 반환하지 않음.
- DELETE는 기존 관리 토큰으로 잠금 중에도 취소 가능.
- `unlock_at` D1 컬럼 추가; 기존 행은 NULL로 간주. 서버에서 날짜·만료·제한을 판정.
- **중요**: 기존 `effectiveExpiry = min(expires_at, created_at + 10일)`, `sweepExpired`의 `created_at + 10일` 조건, `reserve`/우표 원장의 10일 기준, R2 **11일 자동 삭제** 규칙은 예약 엽서를 파괴한다. 이 경로 모두 특별 우표 예외로 분리해야 한다.
- R2: 예약 콘텐츠는 별도 `nangman-postcard-scheduled/` 접두사 또는 별도 버킷으로 분리해 11일 수명주기 규칙에서 제외. 서버 만료 정리 + 안전한 별도 장기 보관/삭제 정책 필요.
- OG 미리보기는 중립 봉투만 표시. Cache-Control: no-store. 링크 토큰은 로그·외부 분석에 유출 금지.
- 앱·서버의 special 우표 카탈로그 활성화 시점을 맞추고, 구버전 클라이언트는 즉시 발송 유지.

## 배포 게이트
- 서버가 잠금 중 배경·획을 절대 반환하지 않는 자동 테스트
- 1시간/365일 경계, 시간대, 10일 만료, 취소, 저장 용량 제한, 구버전 호환 테스트
- R2 수명주기 정책을 실제 Cloudflare에서 확인
- iOS TestFlight 빌드, 웹 배포, 실제 Safari·카카오 인앱브라우저 확인
- 위 검증 전에는 예약 UI를 실서비스에 노출하거나 성공을 표시하지 않음
